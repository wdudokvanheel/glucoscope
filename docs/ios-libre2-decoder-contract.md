# iOS Libre 2 production decoder contract

**Implemented engineering boundary — 11 September 2026. No production decoder is promoted or connected.** `Libre2ProductionDecoder.swift` now implements the pure types, structural validation and engineering slot calculations after the isolated v8 locked-storage result. The running app still uses `Libre2DiagnosticDecoder` for transient experimental values and `LibreCollectionCoordinator` for session metadata only. Passing these engineering checks does not establish sensor accuracy, current sensor health or suitability for treatment decisions. No revision has the independent numerical evidence required for canonical ingestion.

This contract is grounded in [the protocol specification](libre2-eu-protocol.md), [the ingestion design](ios-libre2-ingestion-design.md), `LibreVerifiedFrame`, `LibreCalibration`, `LibreSensorClockAnchor`, `LibrePersistenceBridge`, and `ReadingStoreTypes`/`ReadingStore`. The implemented rules below remain engineering decisions awaiting qualification; the existing diagnostic bounds are not automatically production acceptance criteria. Persistence-adapter, serialized writer ownership and runtime-qualification requirements remain unimplemented.

## Input ownership and whole-frame rejection

The pure production decoder takes one immutable `LibreVerifiedFrame`, the matching reconciled `ReadingSessionSnapshot`, an optional `Libre2DecodeOwnership` snapshot and a versioned `Libre2ProductionPolicy`. A missing ownership snapshot means collection is disabled; a present snapshot must match the captured generation, full session and durable ID exactly. This caller-supplied synchronous comparison cannot itself prove current ownership or authorize a commit. It never loads Keychain, reads the current UI pairing, repairs a clock, accesses storage, or accepts a diagnostic result as input. The coordinator establishes transport generation and durable wear identity before decode and rechecks ownership after asynchronous preparation and before submitting work. The production writer needs an explicit ownership check serialized with the decision to commit; a check before an `await` alone cannot prevent an invalidated callback from committing. Implement and test that boundary before connecting ingestion; the current generic `ReadingStore.ingest` has no generation argument.

Whole-frame rejection produces **zero accepted slots** and a stable, redacted reason:

| Check | Required rule |
| --- | --- |
| Ownership | Current enabled generation, completed captured setup, exact captured pairing/calibration/clock, valid durable wear UUID, matching stable fingerprint and revision. A later counter reservation or discovered peripheral cannot relabel bytes. Missing ID, replaced wear, stale generation or unexplained clock mismatch blocks submission. |
| Integrity | Exactly 44 plaintext bytes; recompute the protocol CRC over `0..<42` and compare the little-endian trailer `42..<44`. Normalize sliced `Data` indices before indexing. CRC detects corruption; the plaintext has no UID and cannot authenticate ownership itself. |
| Revision | Classify the complete patch with `Libre2Protocol.classify`; exclude Plus, US and unknown/incomplete patches. Production additionally requires evidence for that exact revision and algorithm/policy version. The parser recognizes EU `9D`, `C5` and non-Plus `7F`; only one `7F` has diagnostic hardware evidence, and none is qualified for promotion. |
| Calibration | Format 1, exact 10-byte compact source, 8-byte owner UID, stable owner identity (patch bytes 4–5 excluded), usable capture date and capture minute `0...20880`. Snapshot lifecycle must be `02` or `03`. Structural decoding validates these before coefficient access; do not accept caller-constructed unconstrained integers. |
| Clock/session | Format 1, matching owner and wear, reference minute `0...20880`, finite usable date, 60-second nominal resolution and supported canonical provenance. Reconciled SQLite clock is authoritative; the bridge currently allows at most 0.001 seconds of representational date difference. Derive final dates from that canonical clock. Never re-anchor using receipt time or a later calibration capture. Session metadata, pairing creation, calibration capture and receipt dates must satisfy the store's inclusive epoch range `946684800...4102444800` (2000-01-01 through 2100-01-01 UTC); require coherent first/last observation order. |
| Frame age | Read minute `M` from bytes 40–41 little-endian. Require `referenceSensorMinute <= M <= 20880`. The reference-minute floor rejects an entire older frame; individual recovery slots may precede the reference. This is the existing rollback rule, not monotonic stream/replay detection. There is no minute-wrap extension. |
| Common conversion | `i2` in `1...1023`, `i4 > i3`, `i6 > 0`, and finite coefficients with strictly positive sensitivity. Reject unsupported coefficient regimes; never substitute a generic multiplier. |
| Qualification | Missing numerical, lifecycle/status or clock/freshness policy qualification blocks the canonical path. A successful diagnostic calculation cannot bypass this gate. |

Lifecycle `02`/`03` was observed during an earlier NFC read. It does not prove the sensor is currently starting/ready, and an old ready capture cannot rule out a later error or expiration. `ReadingSessionLifecycle.active` describes the app's wear record, not decoded live sensor state. The payload parser does not interpret bytes `28..<40`; do not label those bytes as a validated status field, infer health from zero/nonzero patterns, or treat constant glucose as expiration. They remain CRC-covered uninterpreted bytes. Fresh live-state semantics and acceptable handling of unknown/error states remain qualification blockers, with no automatic NFC scan requested.

## Per-slot parsing, dates and conversion

After whole-frame validation, produce seven results in wire order with offsets `0, 2, 4, 6, 7, 12, 15`. Each four-byte little-endian word starts at `4 * slotIndex`:

| Field | Domain |
| --- | --- |
| Raw glucose `G` | bits 0–13, `0...16383` |
| Raw temperature `T` | bits 14–25 multiplied by 4, `0...16380`, multiples of four |
| Adjustment `A` | magnitude bits 26–30 multiplied by 4; bit 31 sets negative sign, `-124...124`, multiples of four; negative zero is zero |
| Calibration fields | `i1: 0...7`, `i2: 0...1023`, `i3: -255...255`, `i4: 0...16383`, `i5/i6: 0...16380` in multiples of four. `i1` and `i5` are retained but unused by the selected nonlinear equation. Their omission still needs algorithm qualification. |

Let `S = M - offset` using checked signed arithmetic. Reject a slot with `S < 0` as `sampleBeforeStart`; do not create a timestamp for it. Reject `0 <= S < 60` as `warmup`. These are individual failures: a recent usable slot survives a negative or warmup recovery slot. A sample with `60 <= S < referenceSensorMinute` is permitted, and uses a negative delta from the original anchor. Do not clamp that delta to zero or confuse it with the whole-frame rollback rule.

For an otherwise eligible slot, compute `canonicalReferenceDate + 60 * (S - canonicalReferenceMinute)` with checked subtraction and finite multiplication/addition, then enforce the same 2000–2100 store date range. An out-of-range sample date rejects only that slot; a malformed common anchor rejects the entire frame. Dates are UTC coordinates, independent of receipt delay and timezone. Calibration capture minute/date are provenance, not a replacement anchor or a new per-slot minimum.

Use the documented full nonlinear equation and finite-domain coefficient reconstruction, with the exact algorithm/version recorded. Check operands and every intermediate before division, logarithm, exponentiation, rounding or integer conversion:

1. Reject zero `G` or `T` individually. Check `i6 + A > 0`, finite positive resistance `R`, finite `log(R)`, and finite positive inverse Kelvin `D`.
2. Require finite Celsius temperature `C`. The proposed initial engineering temperature domain is the existing `-10...60` °C inclusive; it is not a manufacturer operating-range claim and needs qualification.
3. Require finite normalized glucose, exponent/power factor, corrected value and final mg/dL. Fixed-width integer intermediates use checked arithmetic or conversion into the already bounded floating-point domain before arithmetic. Never allow a conversion trap, NaN or infinity into a result or date formatter.
4. **Implemented engineering numeric policy:** require the unrounded result in `20...600` mg/dL inclusive, then round once using nearest integer with ties away from zero (`rounded(.toNearestOrAwayFromZero)`). Check exact integer representability and recheck `20...600` before creating an accepted slot. Thus 19.9 and 600.1 are rejected, 20 and 600 are accepted, and 20.5 becomes 21. No clamping, low/high surrogate, mmol/L round trip, fallback, averaging or interpolation occurs. The store already enforces integer `20...600`; this alignment is an engineering storage policy, not an established measurement range or accuracy tolerance. Diagnostic `1...1000` Double values remain a separate domain. If qualification requires another range, change the versioned policy and store validation together before promotion.

A bad slot never supplies a candidate, and never invalidates good siblings solely because of its own raw value/domain/date. Return seven explicit outcomes even when all are rejected; this is distinct from whole-frame rejection. Preserve stable reason codes and counts, not raw calibration or payloads, in routine rejection summaries.

Receipt time is provenance and an input to future freshness assessment, never the sample timestamp. No acceptable maximum sensor-to-phone clock offset, receipt age or lifecycle-snapshot age has been established. The 60-second clock resolution allowance does not bound phone-clock error, capture latency or drift. Specify and test those policies before promotion; do not silently assume sample dates must precede receipt (the v5 observations were 15–16 seconds ahead). Old valid recovery samples belong in history; they must never make the current-value display appear fresh. Replay/order handling is coordinator work: duplicates can add no new canonical reading, lower arrival minutes alone cannot invalidate missing recovery slots, and a stale current-value status must not reset merely because a CRC-valid packet arrived.

## Result types and persistence boundary

`Libre2ProductionDecodeResult`, `Libre2AcceptedSlot`, `Libre2SlotRejection` and `Libre2SlotOutcome` are now implemented, with decoder-restricted initializers for production results and accepted slots. Their redacted `Libre2DecodeContext` retains wear/generation/sequence, receipt and version provenance. Context receipt provenance is optional and omitted when the original receipt date is nonfinite or outside the supported date range; no fabricated receipt date is substituted. The only policy is `engineeringV1` (`libre2-production-engineering-policy-v1`); it always reports `canIngestCanonical == false` and the numerical-evidence, live-status, clock/freshness and writer-ownership blockers. The normal `decode` entry point validates common inputs, then rejects otherwise valid frames as `unqualifiedPolicy` with zero slots. There is no caller-set qualification flag.

The separate `Libre2EngineeringEvaluation` and `evaluateEngineering` entry point exist only when compiling the portable fixtures with `LIBRE2_ENGINEERING_DECODER_FIXTURES`. This flag is absent from the app target and is not implied by `DEBUG`. Engineering evaluation produces either a whole-frame rejection or seven outcomes bound to the immutable context; it cannot return a successful production result. The decoder version is `libre2-nonlinear-production-v1`. The equation shares only the finite-domain coefficient helper with the diagnostic decoder; it consumes no diagnostic result or diagnostic acceptance rule. An accepted slot carries sensor minute, integer canonical mg/dL, canonical-clock timestamp and fixed algorithm/quality identifiers; its initializer is restricted to the decoder file. A rejected slot can carry its index, offset, signed minute and reason; it need not have a timestamp or numeric value. Raw bytes/calibration/temperatures are not fields of an accepted persistence result. The versioned quality `engineeringChecksPassed-v1` describes engineering checks without asserting clinical validity or live sensor health.

Only a dedicated coordinator adapter may turn accepted production slots into `ReadingCandidate`: captured receipt time, `.trend` kind for all BLE slots, `.bleLive` for offset 0 and `.bleHistory` for older offsets, and the exact promoted decoder version. `ReadingCandidate` deliberately contains no sample timestamp or session ID; `ReadingSubmission` owns the bridged session, and the writer derives sample dates from its canonical session clock. Diagnostic types must have no adapter or implicit conversion into this path. The production result itself is neither `GlucoseMeasurement` nor a local graph/upload source.

Submit frames serially in process sequence order; the sequence identifies callback order, not sample identity and not a persisted anti-replay counter. `ReadingStore` currently serializes received operations but does not sort them by sequence; the future coordinator must enforce submission order and bound backlog explicitly. Current metadata coordination may replace its one pending frame; do not silently reuse that policy for canonical candidates without reporting dropped/uncommitted slots and testing recovery limits. Within each submission accepted candidates may be ordered by ascending sensor minute. Whole-frame rejection or zero accepted slots creates no reading/delivery transaction.

Deduplicate on `(wear UUID, sensorMinute, sampleKind)`. Overlapping and reversed arrivals with equal values preserve one canonical row and its one required delivery row; sparse gaps stay absent. For conflicting values the first committed reading wins, so outcomes are intentionally arrival-dependent for disagreements. Existing duplicate rules compare integer glucose exactly and sample date with the configured tolerance (default one second); they merge origin flags only on agreement and otherwise record a redacted conflict without replacing values, dates, quality, primary origin, decoder version or frozen payload. These conflict tolerances are not numerical-validation tolerances. Equal glucose at distinct minutes is not a duplicate.

Only `ReadingStore`'s successful atomic save of each reading plus its required delivery row allows canonical display, graphing or delivery scheduling. With no destination the row is `unassigned`. Commit IDs are new inserted reading IDs sorted chronologically; conflicts and exact repeats do not create replacement readings. Save failure publishes no canonical candidate. A successful save followed by failed publication is already durable and must be reconciled by refetching, not recanonicalizing diagnostic values. A stale generation detected before commit must publish no new reading; a later sensor switch does not delete previously committed history. The independent v7/v8 metadata probes establish none of these production reading-transaction device guarantees.

The expanded `./ios/Libre2Tests/run.sh` suite passed all nine executable runs on 11 September 2026: the existing seven plus separate normal-gate and engineering-fixture builds of `ProductionDecoderSmoke.swift`. The latter checks immutable/sliced inputs, common rejections, all recognized revisions remaining unqualified, seven sparse outcomes with mixed failures, five fixed independently calculated rounded expectations, quantizer bounds/ties/nonfinite inputs, canonical-clock reconciliation, per-slot warmup/date boundaries and the lifetime endpoint. Invalid receipt dates reject with absent context receipt provenance. These fixtures validate engineering behavior only; they do not exercise a production writer admission boundary or establish sensor accuracy. Detailed fixture provenance is in [the test README](../ios/Libre2Tests/README.md).

## Evidence required before promotion

Keep three kinds of evidence separate:

1. **Deterministic engineering fixtures:** synthetic packed bytes and independently calculated expected results for all coefficient regimes/boundaries, signed adjustment, zero/raw-domain failures, nonfinite arithmetic, warmup/negative/before-anchor slots, date limits, sliced input, CRC, identity, missing clock and unqualified revision. Test mixed per-slot outcomes, rounding ties and values immediately outside 20/600, duplicate conflicts and invalidation across the future write boundary. Existing arithmetic fixture tolerances (`1e-8` mg/dL, `1e-10` °C, `1e-14` coefficients) compare computations only; they do not authorize a sensor-accuracy claim.
2. **Independent numerical comparisons:** before evaluating a new comparison set, record its reference/device/software and algorithm configuration, units/display rounding, how sample timestamps are obtained/aligned, collection conditions, planned sample coverage, allowable timestamp-matching window, acceptance metric/tolerance and minimum evidence count. Those last three are presently **unset**, so there is no passing accuracy result. The independent reference must measure/report the corresponding samples, not reuse this decoder's output. An offline reference implementation can check equation agreement but cannot alone qualify the sensor against the usual reader/official algorithm.
3. **Revision and runtime qualification:** record revision, app/decoder/policy version, wear phase and calibration/clock provenance without committing raw identifiers. Exercise appropriate low/middle/high observations and changing/stable sequences as available during ordinary use, rejection/error/lifecycle behavior, recovery and relaunch clock stability. Do not induce glucose changes or interrupt the user's usual reader to fill a fixture category. Resolve clock/freshness and uninterpreted-status limitations explicitly. Each new revision needs its own evidence; storage and transport success do not transfer numerical qualification.

For a user-owned comparison run, preserve each app sample's sensor minute, anchor-derived UTC time, receipt time, unrounded diagnostic mg/dL, proposed canonical integer, slot offset and decoder version. Pair it with the independent reference's sample time, value and units; record timestamp uncertainty and the reason for every unmatched/excluded sample. Compare like-for-like units and retain signed/absolute differences and the full planned denominator, including rejections. Preserve source evidence privately and put only redacted aggregates/methodology in the repository. Choose a feasible acquisition method first: simultaneous two-phone collection/takeover is not qualified, and switching collectors does not itself produce timestamp-matched samples.

The qualitative report that values “seem to match” has no exact pairs, configured reference, timestamp window or agreed tolerance and remains insufficient. No hardware action is needed for this pure decoder increment. Xcode builds and app/device runs remain user-owned and unverified for this source revision. The production types and policy fixtures are now present behind the disabled runtime boundary; numerical evidence, status/freshness qualification, writer ownership tests and user-owned build/device validation must precede enabling canonical ingestion. No normal graph, backend delivery or NFC history integration is authorized by a diagnostic pass alone.
