# Libre 2 decoder comparisons

The decoder uses the full nonlinear equation documented in [the protocol](libre2-eu-protocol.md). Software fixtures and device observations help find mistakes while local collection and app development continue.

## What has been checked

- Five fixed synthetic glucose expectations were calculated independently with Python Decimal at precision 60, using calibration indices 1, 513, 720, 952 and 1023. Tests contain constants rather than expectations generated by the Swift implementation.
- The finite coefficient reconstruction was checked against all 1,023 supplied source entries. The original coefficient generator is unavailable.
- One non-Plus `7F` has produced diagnostic values on a phone. The user reports two exact matches to their reference's preceding-minute display. No numeric trace or matching sample timestamps were supplied, so these are useful spot checks, not a measured accuracy result.
- `9D` and `C5` have synthetic parser coverage, with no physical results supplied.

The reference has no timestamped history export, and the user is currently using that reader. No repeat comparison or collector switch is needed to continue software development.

## Useful software checks

Run `./ios/Libre2Tests/run.sh`. For added decoder cases, calculate expected fields and values independently from packed bytes, calibration and the equation. Cover coefficient boundaries, signed adjustments, invalid domains, CRC/identity failures, warmup, sparse offsets and clock reuse.

The existing moderate-temperature vectors use absolute tolerances of `1e-8 mg/dL`, `1e-10 °C` and `1e-14` for coefficients. These are fixture tolerances, not physical accuracy thresholds. Integer storage must match the expected integer exactly: require unrounded `20...600` mg/dL, then round once with ties away from zero. Test ties and neighbors without allowing a floating-point tolerance to cross a rounding or rejection boundary.

## When a device comparison is available

Record app/reference versions, sensor revision, original units and the meaning of each timestamp. Match corresponding samples by time or sensor minute before comparing values. Keep packet receipt and export time separate from sample time, and count repeated sparse observations only once per sensor minute.

Report the matched values, signed and absolute differences, unmatched samples and rejection reasons. A preceding-minute display can be useful context without being assumed to identify the same sample. Preserve missing information as missing; do not shift timestamps to make glucose values match.

The selected equation differs from the reference transmitter's rounded four-point bilinear path and optional calibration adjustments. Identify which algorithm and settings produced a reference value when known. Agreement with another calculation checks that comparison; it does not establish clinical accuracy.

Detailed diagnostic exports retain the latest frame with glucose rounded to one decimal mg/dL and two decimals mmol/L (`18.0182` mg/dL per mmol/L). They lack compact calibration bytes and full floating-point precision, so they cannot reproduce an exact raw-input calculation. Keep private frames, calibration and glucose traces outside the repository; commit synthetic fixtures and concise findings.
