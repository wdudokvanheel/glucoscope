# Libre 2 portable regression tests

Run `./ios/Libre2Tests/run.sh` from the repository root on a Mac with the Swift toolchain. The script compiles app-owned protocol/models, the diagnostic and production decoder boundaries, identity helpers, Core Data reading store and guarded commit boundary, collection coordinator, persistence bridge, disconnected ordered-ingestion/candidate-adapter scaffolding and storage probe into thirteen executable runs. It does not import xDrip, build or launch the app, access the device Keychain, or need NFC/BLE hardware. Persistence fixtures use in-memory stores and temporary SQLite files that are removed after each run.

The UID and packet fixtures are synthetic. BLE plaintext is bytes 0 through 41 with its reference CRC. FRAM plaintext follows byte `(index * 7) mod 256`, has lifecycle byte 4 set to 3, and has independently computed section CRCs. Ciphertexts and expected unlock commands were checked using the supplied reference functions in a temporary comparison harness outside the app/repository. Reference file hashes are recorded in `docs/libre2-eu-protocol.md`. No glucose conversion or algorithm configuration is involved.

Tests cover fixed NFC/BLE authentication payloads, encrypted BLE and full FRAM plaintext, single-bit corruption, wrong UID, malformed inputs, supported/rejected revisions, the last counter reservation, every two-fragment split, byte-at-a-time reception, overflow recovery, and connection/timeout buffer reset. Core Bluetooth callback ordering, actual timers, Keychain fault injection and physical NFC cancellation need hardware/integration validation; these pure tests do not establish those behaviors.

NFC read recovery tests additionally exercise success after transient failures, attempt exhaustion, cancellation between attempts, and immediate failure for a non-retryable operation. They use the same main-actor retry runner as the NFC session and do not communicate with a sensor. Polling/redetection and Core NFC error delivery still require physical validation.

Calibration fixtures additionally cover the packed EU extraction layout, shifted `Data` views at the capture boundary, versioned round trips, invalid/foreign calibration, legacy pairing migration, and merging into advanced session state. Shifted valid, CRC-corrupt and unsupported-lifecycle FRAM inputs verify that fixed protocol offsets cannot trap on a nonzero collection index. They are synthetic and do not verify glucose conversion. All ten portable executable runs, including these slice regressions, passed on 11 September 2026. The user-built v5 app also passed the bounded read-only NFC recapture, following-frame and relaunch sequence documented in `docs/libre2-ble-testing.md`; remaining NFC control-flow, serial BLE integration and Keychain save-failure cases still require separate device/integration checks.

The script also compiles `DiagnosticDecoderSmoke.swift` as a separate executable with the pure diagnostic decoder. Its fixtures cover all seven sparse offsets, full packed sample and calibration widths and both adjustment signs, zero/mixed slots, temperature domains and diagnostic bounds, identity/revision/version, CRC/length, warmup and 14.5-day lifetime boundaries, a starting lifecycle snapshot after warmup, timestamp overlap and persisted anchor reload. Repeated identical valid glucose is accepted. Invalid/missing slots are never interpolated.

Five fixed glucose expectations were calculated independently using Python Decimal at precision 60 from the full nonlinear equation and selected reference coefficient entries. Absolute tolerances are `1e-8 mg/dL` for those synthetic glucose vectors, `1e-10 °C` for temperature, and `1e-14` for coefficients at every table-regime boundary. Expectations are constants, not values generated by the implementation under test. CRC-bearing mutation fixtures use a separate unreflected polynomial recurrence. All inputs are synthetic; no physical raw packet exports or sensor identifiers are included.

`ProductionDecoderSmoke.swift` is compiled and run twice. The ordinary compile has no engineering fixture flag and verifies that every recognized revision remains blocked by the unqualified canonical policy; the engineering evaluation API is absent from that source shape. A second portable executable is compiled with `-D LIBRE2_ENGINEERING_DECODER_FIXTURES` to exercise deterministic parsing without granting runtime eligibility. Its fixtures cover immutable frame ownership, stale generations and pairing changes, sliced input, whole-frame identity/integrity/calibration/clock/session rejection, all seven sparse outcomes, mixed per-slot failures, canonical date and lifetime endpoints, pre-anchor recovery, warmup, invalid receipt dates, integer rounding boundaries and independently expected nonlinear results. The production types remain disconnected from `ReadingCandidate`, `ReadingStore`, graphing and upload.

The selected `libre2-nonlinear-diagnostic-v2` equation retains signed adjustment and differs from the supplied transmitter's rounded four-point bilinear approximation. Version 2 preserves the earlier glucose equation and consumes a separately persisted sensor clock. The coefficient reconstruction, exact algorithm selection, source hashes, engineering bounds and clock limitations are documented in [`docs/libre2-eu-protocol.md`](../../docs/libre2-eu-protocol.md). Table reconstruction was inspected arithmetically across the finite source domain; the original generator is unavailable. These fixtures do not establish medical accuracy or official sensor agreement.

Stable-clock regression fixtures use two new calibration captures whose implied clock estimates shift by -6 seconds and then +22 seconds. Both decodes explicitly reuse the saved clock, including a Codable reload, and require overlapping sample minute 1000 to remain epoch second 1700000000. Missing/foreign anchors are rejected, and nonfinite capture dates cannot construct calibration/clock data. Session-model fixtures cover legacy migration, first capture, recapture, explicit null and malformed clock persistence, foreign/out-of-lifetime anchors, deliberate clock repair, the 20,880-minute lifetime endpoint, and preservation of pairing counters/peripheral. Both portable executables include `LibreSensorClockAnchor.swift`.

Diagnostic export revision v5 separates calibration capture metadata from the saved clock reference. On an existing v4 installation, migration preserves the latest calibration estimate available in storage; overwritten earlier anchor metadata cannot be recovered. The clock fix establishes stability from migration onward, while initial minute-resolution and device-clock uncertainty remain.

All thirteen portable executable runs passed on 11 September 2026, including both production decoder source shapes, the fixture-only guarded commit race, both candidate-adapter source shapes and the ordered mailbox. The existing corrupt-store fixtures emitted their expected Core Data 259 / SQLite 26 diagnostics; there were no compiler warnings. The user owns Xcode builds, app/device execution and physical value comparisons; no agent-run `xcodebuild` result exists for this increment. The engineering fixtures do not qualify canonical graph/store/upload readings.

`IdentitySmoke.swift` exercises versioned wear-session identity and the pure Keychain migration boundary. It verifies save-before-return, failed writes, restart between Keychain migration and store insertion, invalid-present identities that remain invalid after counter saves and Codable round trips, and stale legacy counter saves that retain the durable UUID. Same-wear repair fixtures cover mutable patch bytes, pairing timestamps/peripheral changes, calibration recapture, lifecycle progression and retention of the original clock. Conflicting clock/minute/lifecycle evidence requires repair; physical sensor replacement gets a separate identity. A fixed SHA-256 expectation independently checks the stable fingerprint format. The runner compiles the Security-backed session store but never calls Keychain.

`ReadingStoreSmoke.swift` supplies synthetic integer glucose candidates directly to an isolated Core Data store; it does not link the diagnostic decoder. It covers sparse overlap, repeats, reverse arrival, concurrent callers, BLE/NFC trend deduplication, distinct 15-minute history, chronological commit IDs and retained gaps. Every committed reading must have one delivery. Later destination assignment and initially configured ingestion queue payloads atomically; replay/conflict preserves canonical values and frozen payloads.

Fault fixtures inject reading-save, destination-assignment-save and store-load failures, check rollback and explicit unhealthy state, and retry without partial reading/delivery pairs. A concurrent submission burst must stop after its first writer fault until explicit retry; concurrent store opening must remain usable. A fault after the SQLite save but before publication must publish no commit while retaining all durable rows. Tests inspect both snapshots and the actual commit stream. Closing and reopening the actual SQLite store then verifies stable identities, destination state, exact payload bytes and replay deduplication. A genuinely corrupt SQLite file must fail to open and remain intact; this fixture intentionally prints Core Data error 259 / SQLite error 26. Fingerprint and clock disagreements cannot relabel or re-anchor an existing wear session. Out-of-range dates/minutes must reject without integer-conversion traps, and retry cannot bypass invalid configuration.

`CommitOwnershipSmoke.swift` enables a portable fixture flag that is absent from the app target and exercises the explicit guarded writer entry point without a decoder or runtime adapter. Admissions are bound to one captured frame sequence, reconciled wear snapshot, durable UUID and receipt time. Missing/stale ownership, replacement, reconnect, disabled collection and mismatched submission data are rejected while the store remains healthy. Deterministic barriers pause after staging and while the writer owns the revocation lock: invalidation that wins before admission rolls back session metadata, duplicate origin merges, conflict rows, new readings and deliveries; a save that wins completes before invalidation and remains committed. An exact no-change duplicate still requires current ownership. Separate pre-save and post-save faults verify complete rollback and explicit retry versus durable SQLite rows with no publication. Sliced captured UID and patch views verify admission normalization without weakening immutable frame comparison.

`CandidateAdapterSmoke.swift` is compiled twice with the complete disconnected ingestion stack. The ordinary source shape has no fixture flags and verifies that the closed normal decoder cannot reach candidate persistence. The fixture shape alone enables `LIBRE2_CANDIDATE_ADAPTER_FIXTURES`, `LIBRE2_ENGINEERING_DECODER_FIXTURES`, `LIBRE2_ORDERED_INGESTION_FIXTURES` and `LIBRE2_COMMIT_OWNERSHIP_FIXTURES` for deterministic positive and adversarial binding checks. None of those flags is present in the app target.

`OrderedIngestionSmoke.swift` enables only `LIBRE2_ORDERED_INGESTION_FIXTURES` and exercises the disconnected bounded mailbox around synthetic frame work. The source policy retains at most eight active-plus-queued frames, drops newest work on overflow, enforces the 120-second monotonic pre-submission residence checks and serializes processing by increasing offered sequence while allowing gaps. This executable does not connect the mailbox to Core Bluetooth or promote decoder policy.

The new fixtures test the queue, metadata preparation, adapter mapping and guarded store at explicit isolated boundaries. They do not yet drive reversed sensor-minute/conflicting-value frames through the ordered adapter, race a concurrent offer against invalidation, or exercise the eventual Core Bluetooth handoff before its asynchronous diagnostic relay. Publication-recovery fixtures verify at most seven unique keys from the exact durable transaction, show that unrelated corrupt history is outside that check, and keep the adapter blocked when a required target delivery is missing. This transaction-key check is storage integrity only: a full-history `ReadingStore.snapshot()` is not an acceptable recovery mechanism, and graph/current-value consumers still need their own paged or range-bounded refetch contract before runtime UI integration.

`CollectionCoordinatorSmoke.swift` compiles the immutable frame envelope, shared generation gate and main-actor coordinator with guarded-admission support, while omitting the `ReadingStore` implementation and diagnostic decoder. A synthetic decode seam verifies rejection of old connections, replaced wear, duplicate and out-of-order callbacks before decoding. Fixtures verify captured payload/session/calibration/clock value semantics, process-local sequence continuity, bounded store retries, redacted load/bridge failures with diagnostics continuing, and delayed metadata completion after stop or replacement. A burst during a suspended preparation retains only the latest pending frame. A concurrent critical-section fixture checks that generation invalidation cannot interleave with the short current-frame compare-and-save boundary.

`PersistenceBridgeSmoke.swift` uses real in-memory Core Data metadata operations and an injected Keychain boundary. It covers migration write failure, rollback after identity migration but before metadata save, UUID retention across a restarted bridge, canonical clock disagreement, deliberate missing-clock restoration, preservation of later counter/peripheral/calibration changes, and rejection of replacement or foreign ownership. A suspended canonical-clock lookup completed after invalidation cannot save into the replacement pairing. The repair mock calls the same pure compare-and-update helper used inside the real Keychain lock. Metadata preparation and repair must leave readings, deliveries and published reading commits empty. This executable deliberately does not link the diagnostic decoder.

`StorageProbeSmoke.swift` exercises the deliberate runtime probe with synthetic session/clock metadata only, zero readings/deliveries/destinations/conflicts and no production ingestion dependency. It checks initialization without filesystem activity, explicit actions, ignored overlapping clicks, exact SQLite close/reopen verification, same-process instance recreation that cannot claim relaunch, and retained metadata verification by a separately launched executable after the seeding process exits. Missing/corrupt manifests and SQLite files, an incomplete marker and unexpected records must fail without reseeding or repair. A production-path sentinel remains untouched and a symlink probe directory is refused. Actual file observations cover SQLite/WAL/SHM while open and before reopening; macOS reports iOS protection inspection as unsupported. The corrupt SQLite fixture intentionally prints Core Data errors.

The same executable injects protected-data availability, app foreground/background state and a bounded background-task lease into the separate locked-probe path. It verifies that foreground, protected-data-available, cancellation, timeout and expiration remain inconclusive; that a qualifying synthetic sequence performs a fresh metadata mutation plus read/close/reopen without accumulating rows; and that stale expiration, mid-operation invalidation, missing/corrupt stores and overlap cannot produce late success or touch the v7 fixture. A passing macOS sequence sets only `lockedSequenceCompleted`; it deliberately cannot set the iOS-only `lockedVerified` result.

The app may open the protected store and reconcile sensor metadata, but live diagnostic glucose remains disconnected from canonical readings, the production viewer, graph and upload paths. These tests do not establish Core Bluetooth callback ordering, graph trend/history selection, acknowledged delivery transitions, backend contracts, or abrupt process termination during a write. The reading-store post-save interruption is a deterministic fault hook followed by store close/reopen; the storage-probe executable adds ordinary separate-process persistence and injected lifecycle control flow, not real UIKit scheduling or device-lock qualification. Device-only checks remain for real Keychain/platform failures, actual app relaunch, locked protected-data availability, reboot before first unlock, background collection and independently timestamp-matched decoder accuracy. Protection attributes and injected state alone do not prove locked-device accessibility. No agent-run Xcode build or device execution is part of this suite.
